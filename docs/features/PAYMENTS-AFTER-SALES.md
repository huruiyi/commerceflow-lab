# 支付、退款与售后

## 支付如何完成

商城按订单应付快照创建支付宝、微信支付或银联模拟收银台。顾客可以查看支付回执，失败或尝试过期后可在整单付款期限内换渠道。支付编排持有支付与退款记录。模拟平台回调校验签名、时间戳与随机数，回调与 Outbox 事件可重试，重复处理使用幂等键。库存预占凭证通过门禁后才允许付款，成交后提交库存扣减。

## 全额退款与按行部分退款

- 已支付未发货订单可整单原路全退。顾客和商家可查看退款状态及渠道结果。
- 顾客从订单行发起部分退款，可先查看剩余数量和可退金额，再提交数量与原因。商家审核。未发货部分退款同步收窄履约范围，退款达成后回补对应数量。
- 已收货实物可按订单行申请退货。商家同意后，顾客在售后详情填写承运商、退货运单号和可选退货运费，顾客与商家都可以查看同一份退货轨迹。
- 新登记的退货在物流送达后进入待商家验收。商家录入实际收货件数、货品是否可销售以及处理说明。数量不符或货品不合格进入人工复核。验收通过后才执行原路退款和库存回补。历史仅有运单号的退货显示轨迹未知，仍按实物验收。
- 同一支付单可有多笔退款，各笔独立对账。请求 ID、退款编号和库存回补操作 ID 用于幂等。累计退款受原支付金额约束。

## 实付、运费与库存

商品退款以购买时订单行净额为基础。订单用了优惠券时，先扣除该行的优惠分摊再计算可退金额。先前已处理的数量和金额会占用剩余额度。未发货场景首笔部分退款保留运费，全部商品退款完成时由最后一笔结算符合条件的原运费。已发货退货默认保留原运费。库存只根据真实补偿或实际验收数量回补，每次操作有唯一流水。

单仓多包裹订单部分发货后，商家可审核剩余未发货数量的退款。同一订单行已出库的件数占用发货额度，
剩余应发数量随已完成的未发货退款扣减。已发包裹继续运输，部分退款保留原订单运费。
整单收货后，已发商品按原订单行申请退货。库存以该订单行所有出库包裹的累计数量核对回补上限，
承运商送达退货仍须经过实物验收。详见[单仓多包裹](ORDERS-FULFILLMENT.md#单仓多包裹)。

### WMS 退货实收与质检

退货申请绑定库存出库凭证中的原包裹、订单行和仓号。一条订单行只有一个匹配的出库包裹时自动带入。
一条订单行分多包裹发出时，顾客选择本次实际退回的原包裹。退货数量受该包裹的实发件数和该行已退款数量限制。

1. 商家审核申请后，顾客绑定退货运单。物流送达投影确认后，商城向 WMS 提交带原包裹、仓号和预期件数的退货单。
2. 仓库作业台选择「退货单」，登记实收数量。足量实收后执行质检，合格回执让商城进入「待商家验收」。
3. 短收、拒收、质检不通过进入「待复核」，保持退款与可售库存不变。顾客和商家可以查看实收、质检和待验收状态。
4. 商家验收合格回执后，系统按原订单金额快照退款。支付编排确认退款成功后，库存仅向原出库仓回补。
   商家重复确认沿用同一笔退款和同一条库存回补凭证。

### 售后异常工单

仓库短收、拒收或质检不通过时，商城按售后单号生成工单。商家在「售后异常工单」查看原包裹、仓号、
退货运单、申请件数、实收件数和处置历史，按本店归属办理。顾客在订单售后中查看待补证和处理结果。

- **补证**记录商家的处理要求。仓库在原退货单追加一次签名补检凭证，合格件数受原实收数量限制。
- **拒绝结案**记录处置理由。拒收单可记录物流后续去向和拒收依据，结案不产生退款或库存回补。
- **批准退款与回补**使用补检合格件数、原包裹剩余可退量和订单冻结金额。先确认退款，再向原仓回补。
  原申请件数和首次质检事实留存。未获批件数可以按剩余可退数另行申请。

[工单验收记录](../architecture/FULFILLMENT-SERVICE-EVOLUTION-PLAN.md#34-售后异常工单验收)

### 两仓退款与运费

两仓订单的商品退款使用结算冻结的分仓商品净额。运费份额供对账，各仓份额总和等于整单运费。

WMS 发货等待仓库确认时，订单的发货锁拦截未发退款。短发确认并完成包裹后，以实发件数计算剩余未发件数。
例如单行商品 2 件各 100.00 元、优惠 15.01 元、运费 12.01 元，实际发 1 件后取消余下 1 件，
商品退款为 92.49 元，运费退款为 0 元，只回补原发货仓 1 件。
例如两件各 100.00 元，整行优惠 15.01 元，整单运费 12.01 元。默认仓分到商品实付 92.50 元
和运费份额 6.00 元，第二仓分到商品实付 92.49 元和运费份额 6.01 元。

默认仓发出后若取消第二仓未发数量，退款 92.49 元，库存只回补第二仓。若随后退回默认仓已发商品，
顾客在售后选择原出库包裹，商家实物验收后退 92.50 元，库存只回补默认仓。两次退款均保留原运费。
同一件商品在仓发货和未发退款之间需要通过订单侧数量准入，避免重复使用同一份库存。

## 商家应结账本

管理员在测试或营业店铺的「应结账单」启用结算并输入商品佣金基点。100 基点等于 1%。首版费率随结算账户冻结，从启用后新下单的订单开始记账。管理员可按当前时点冻结应结账单，商家从商家导航查询本店账单和明细。

对已完成订单，账本按订单行成交实付确认商品收入。满减由商家承担，直接体现在行净额里。原运费单列到商家应收，佣金只对商品净额计算。退款以支付编排确认成功及售后台账一致为准。运费退款单列扣回，商品退款按原行费率冲减佣金。活跃售后暂缓对应订单行和运费。账单冻结后的退款在后续账期冲正，未形成正应结额的负余额继续结转。相同出账请求、同一订单行和同一退款分别按各自稳定编号去重。

## 模拟商家打款

管理员打开一张已冻结且应结额为正的账单，点击「发起模拟打款」。商城用账单中的商家、币种和应结金额生成待处理记录。相同请求返回原尝试，同一账单只允许一笔进行中的打款或一笔已成功的打款。渠道明确失败后，管理员可提交新尝试。

后台任务使用稳定的尝试号先查询支付模拟平台，再按需要提交。平台以签名识别专用出款应用，更新独立出款账本并签名回调。商城核对尝试号、账单号、商家、币种、金额和渠道打款号后确认结果。通信超时或进程中断时原打款记录保留，后台按原编号对账。商家可查询本店账单对应的打款状态。

模拟支付后台将「收款与退款」与「商家打款」分为两个菜单。打款只在实验平台模拟。详见 [外部系统模拟器](SIMULATORS.md)。

# 账号、商品与购物车

## 登录与授权

商城门户使用邮箱和密码登录。后端以 BCrypt 保存密码，通过 Redis 管理服务端 Session。勾选记住登录可保留 14 天，注销会撤销对应令牌。写请求由 Angular 结合 CSRF Cookie 和请求头提交。登录失败触发限流。菜单按顾客、商家和管理员角色显示，服务端还会检查订单、购物车、地址和商家资源归属。管理员可查询用户。门户可切换中英文，错误使用稳定错误码。

## 浏览商品与评价

目录服务持有商品资料、翻译、价格、上下架状态与版本。顾客可浏览、搜索和排序商品，详情展示评分和评价。收货后，顾客从订单行进入评价，每行限评一次，评价计入对应商品聚合评分。商家修改自己的商品。库存服务维护各 SKU 的库存并消费目录事件以同步库存所需的商品快照。

## 商家入驻与店铺归属

管理员在「店铺审核」创建商家账号。商家登录后从「我的店铺」提交名称和介绍，审核通过后店铺对外可见。驳回后可修改资料并重新提交。管理员可以停用或重新启用店铺，商家可维护自己的公开名称和介绍。

首版一个商家账号对应一家店。商城 V58 为存量商家回填启用的店铺，原商家 ID 就是店铺的稳定标识。目录商品、库存快照及订单行沿用原商家归属，修改店名不会改变历史订单归属。顾客可从商品详情进入店铺并查看在售商品。

商家从商品管理创建草稿，目录用请求 ID 去重，同一事务发布创建事件。库存收到事件建立零余额快照，商家可按既有库存管理规则调整数量，商品上架后对顾客可见。停用店铺后公开页、商品和新交易入口关闭，原订单的确认、发货、售后和退款仍按成交归属处理。购物车可保存来自多个店铺的商品，每次结算仅选择同一家店的商品。

## 收货地址、购物车与再次购买

- 顾客可新增、编辑、删除地址并设置唯一默认地址。结算时可选择本人的其他地址，订单保存当时的收货快照。
- 相同商品加入购物车时合并数量。顾客可改数量、移除、清空和勾选部分商品。确认下单只清理参与该次结算且数量仍等于原快照的购物车行。
- 已完成订单支持再次购买。系统根据当前商品售价和销售状态重建购物车行，相同商品与已有行合并。同一个请求 ID 重试会返回原回执，数量只增加一次。

# 订单、取消与履约

## 订单和通知

订单服务持有正式订单及其状态。顾客可从订单历史或通知直接进入订单详情，查看金额、地址、付款、物流和可执行操作。商家可查询自己负责的订单并按状态筛查。通知服务消费领域事件，使用 Inbox 去重，在通知菜单提供已读状态和跳转。

未支付订单可主动取消，并设有整单付款期限。仍有待支付渠道时先关闭该尝试，再完成取消、库存释放和通知。持久取消任务负责恢复跨库间隙，即使订单终态已写入而商城暂未生成释放命令，也能继续投递。同一订单的释放和通知按业务键幂等。已付款后的撤销走售后和退款流程。

## 履约、物流与收货

商家确认已支付订单后提交发货。独立履约服务持有发货任务、重试和异常恢复状态，使用稳定请求标识联动库存和物流。出库和运单有各自的状态，门户展示发运信息与轨迹。独立模拟物流可按计划推进、标记异常、恢复和送达。商城接收签名回调，并主动对账缺失投影。

已送达订单可由顾客确认收货，也可由 `AUTO_RECEIVE` 到期自动确认。收货后进入观察期，`AUTO_COMPLETE` 到期后完成订单。观察期和任务触发策略可配置。已完成订单仍能查看物流、查售后和再次购买。

## 单仓多包裹

商家在已确认订单的发货表单中填写承运商、运单号及本包裹的各订单行数量。同一订单行买 3 件时，
可先发 1 件，再为独立运单发剩余 2 件。门户在清单显示部分发货，直到应发件数全部出库。
商家从订单详情查看各包裹，顾客从订单详情查看每只包裹的承运商、运单号和轨迹。
已有的单运单订单仍可查询原运单和历史事件。

订单服务在事务内锁定订单可发数量，扣除已分配和已结算未发货退款的数量。售后准入使用同一订单锁，
发货中断恢复完成前保留原分配。履约任务保存原始订单行和包裹标识，库存以该标识登记出库，
物流以 `CFL-PACKAGE-<包裹标识>` 查询或创建运单。重复请求复用原凭证。注意库存余额在支付后已经提交，
发货阶段写出库凭证和流水，累计出库量不能超过已提交且仍可发的数量。

签名回调按包裹应用并保存轨迹。首包送达时只更新该包裹。全部应发商品已经发出且所有包裹送达后，
商城对账并向订单服务登记整单送达，自动收货按最后一包的送达时间计算。首版范围为单商家单仓，
多仓预占、选路和拆单见[项目计划](../TODO.md#商家经营与后续功能五章)。

## 两仓拆履约

首版提供默认仓与第二仓。商家在库存调整时可指定仓，库存服务先尝试用一个仓发齐整单，
其余订单按仓优先级和编号分配。例如同一订单行买两件、两仓各有一件时，各预占一件。
库存服务在一个事务记录各仓预占，付款要求预占覆盖订单所有商品。存量余额、预占及库存流水归入默认仓。

商城在发起付款前由订单服务冻结每仓的数量、商品原额、行优惠和运费份额。
顾客看到一张订单、一笔支付和各仓包裹，商家可在订单页面按仓提交发货，两个包裹分别建运单、查轨迹和恢复。
各仓只能发出自己已确认的余量。所有仍需发出的数量出库后，订单进入已发货。
两仓的应发包裹都送达后才登记整单送达。首版仍使用现有物流模拟器。

## 退货物流

每笔已获商家同意的退货售后可登记一张运单。同一承运商和运单号只能绑定一笔退货，原数据重试返回同一记录。顾客和商家在售后详情展开轨迹。退货与原订单发货记录分别展示，各自拥有渠道运单号。

登记退货时商城在本地事务保存售后状态和 `REQUESTED` 运单。任务用 `CFL-RETURN-<售后单号>` 查询或创建模拟运单，渠道已建单时查询原运单恢复绑定。物流回调使用签名和稳定事件 ID，迟到事件保存为历史轨迹，当前进度由事件发生时刻和流程规则决定。未送达或刚送达的运单通过主动对账补齐遗漏轨迹。

退货 `DELIVERED` 代表承运商确认送达。系统等待商家验收实物后才退款和回补库存。新登记运单未送达时暂不可验收。历史运单缺少承运商记录时显示「暂无承运商轨迹」，继续通过同一售后入口登记实物验收。退货物流不会触发原订单自动收货或自动完成。

架构与契约见 [架构文档](../architecture/README.md) 和 [独立模拟物流](../MOCK-LOGISTICS.md)。

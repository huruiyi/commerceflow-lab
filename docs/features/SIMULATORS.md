# 外部系统模拟器

| 平台 | 服务与使用方式 |
| --- | --- |
| 支付 | `simulators/payment-platform/service` 提供三渠道收款、原路退款和模拟商家打款，`web` 提供收银台及两个账本菜单。支持成功和失败模拟、渠道查询、关单、退款和打款结果回调。 |
| 物流 | `simulators/logistics-platform/service` 提供签名建单、运单、轨迹、异常处理和回调补偿，`web` 提供物流模拟管理台。 |
| 短信与邮件 | `messaging-platform/service` 提供模拟受理、查询和送达账本，`web` 提供短信和邮件两个菜单。 |
| 仓储 | `warehouse-platform/service` 提供 WMS 实发、短发、退货实收和质检，`web` 提供仓库作业台。 |
| 开票 | `invoice-platform` 预留 `service` 与 `web`，实施顺序见项目计划。 |

支付和物流通过本地模拟系统供商城练习签名、幂等和故障恢复。商家打款复用现有支付模拟平台的服务端和管理后台。专用出款应用访问独立 API，使用独立状态和账本，收款与退款依旧使用原渠道规则。后台按两类业务分设菜单。详见 [商家应结与打款](PAYMENTS-AFTER-SALES.md#模拟商家打款)。

## 模拟后台统一布局

支付、物流、短信邮件和仓库后台使用共用的侧边菜单、面包屑及页面标签。字体栈和间距沿用 Vben Admin 的基础样式，
菜单和标题栏统一使用 Lucide 图标。右上角可用 `Ctrl+K` 搜索当前账号有权访问的页面，支持切换深浅色、
调整布局密度、全屏、刷新及退出。搜索弹窗支持方向键选择、回车跳转及本地历史。
桌面侧栏底部左侧可切换图标栏，右侧可固定菜单。取消固定后悬停展开，移出后收回图标栏。侧栏偏好保存到当前浏览器。
标签栏右侧可管理打开的标签、重新加载当前页和最大化内容区。最大化时收起侧栏和顶部工具栏，标签栏仍可切换页面和还原布局。
右键标签可操作点中的页面，包括固定、最大化、关闭及批量关闭。重新加载只对当前激活的标签可用。
偏好抽屉支持主题、圆角、字体、布局与工具栏选项。时区弹窗使用 Vben Admin 默认的五项单选，初始时区为上海。
确认后更新账本时间并保存到当前浏览器。
取消、关闭弹窗和按 Esc 都保留原有时区。
通知面板记录当前会话的模拟器提示，支持标为已读和清空。支付账号菜单提供安全中心，语言菜单支持简体中文和英文。
模拟后台登录页共用 Vben Admin 原版登录插图和主题变量。支付顶栏直接使用 Vben 的布局组件，
锁定后台会结束当前会话，重新登录后回到原页面。
列表按 Vben Admin 角色管理页的布局组织。收起时保留首要查询条件、搜索、重置和展开入口，
恢复高级条件时保留输入值。列表按 Vben 的自动内容高度布局，标准列表的纵向滚动由表格数据区处理。
少量记录或空结果时，分页条仍位于列表视口底部。
桌面端的记录数和每页条数在左侧，首页、尾页、逐页和跨页控件在右侧。窄屏使用紧凑翻页控件。
VXE Grid 使用 Vben 角色管理页的默认圆角边框，提供分页、刷新、全屏和列设置。同一浏览器会保留列设置。
短信邮件沿用服务端每页 20 条，支付和仓库对当前查询结果支持切换每页条数。

支付概览按 Vben 分析页布局展示四张统计卡、趋势图和三张分布图，下方展示最近交易和安全边界。
趋势图使用后台当前显示时区，按日展示最近 30 个自然日（含当天）。创建笔数按 `createdAt`，成功支付笔数和实收金额
按 `paidAt` 分桶。实收金额为支付成功的 CNY 原金额，按分累计，退款与打款继续从各自账本查询。
渠道雷达图对比创建笔数和当前成功状态笔数，环形图统计当前交易状态，玫瑰图统计模拟场景。
三张分布图覆盖当前账号可见的整份交易账本，趋势仅统计所选时区的近 30 天。
支付的签名交易入口位于渠道交易工具栏。仓库在相应单据的详情中处理出库实发、退货实收、质检和补检。
电子发票后台可复用这些组件。代码位于 `web/packages/simulator-admin`，Compose 使用名为
`simulator-admin` 的构建上下文将其交给各后台镜像。布局和 Grid 配置参考 Vben Admin
`e726bc92780c1023c2393042871470d413ad79dc`，MIT 许可见 `web/packages/simulator-admin/LICENSE.vben`。

日常 Docker 已更新三个前端。Chromium 复验支付筛选、分页、刷新、全屏、列设置和账本切换，
消息渠道切换、筛选和详情，以及仓库单据筛选、详情和 390 px 窄屏。
仓库实发、实收、质检和补检通过浏览器测试夹具核对请求字段。

## 短信与邮件

日常管理台位于 `http://127.0.0.1:18119`，用 `MESSAGING_ADMIN_TOKEN` 登录。
在短信或邮件菜单按业务关联号、投递状态筛选，可查看脱敏收件地址、请求编号、供应商单号与时间。

通知服务使用 `OFFSITE_CUSTOMER_SMS`、`OFFSITE_CUSTOMER_EMAIL`、
`OFFSITE_MERCHANT_SMS` 和 `OFFSITE_MERCHANT_EMAIL` 配置角色测试地址。
使用 555-01xx 测试手机号和 `.test` 邮箱。显式把某个配置设为空可跳过该角色对应渠道。
退款成功和工单新建的消息使用业务事实生成模板，已有投递保留首次记录的模板和值。

通知服务的渠道账本包含 `PENDING` 待发送、`ACCEPTED` 已受理、`RETRY` 待重试、
`DELIVERED` 已送达、`FAILED` 明确失败和 `SKIPPED` 无渠道地址。
渠道超时或触发限流后，任务先查原请求号，再按需要重试。同一业务事件同一渠道使用固定请求编号。
模拟器确认送达失败时记录终态，其他渠道继续。限流、受理后超时和送达失败注入仅供隔离验收。
[业务触发条件](PAYMENTS-AFTER-SALES.md#退款与工单站外通知)

## 物流模拟管理台

本地管理台位于 `http://127.0.0.1:18117/`，使用 `LOGISTICS_ADMIN_TOKEN` 登录，学习环境默认值为 `demo-logistics-admin-token`。

在「运单管理」点击「新建运单」即可创建独立的测试运单，系统自动生成带 `TEST-` 前缀的运单号和订单号，物流单号可留空自动生成。测试运单的事件走实际签名和投递队列，发送给物流模拟服务自己的接收端。选择「正常接收」验证成功投递，选择「持续失败」验证重试与终止；从运单详情点击「查看此运单回调」可直接查看对应记录。

验证回调恢复时，先选择「持续失败」，等回调显示「已终止」。在运单详情或投递详情将「回调模拟结果」改为「正常接收」并保存，再点「重新投递」。保存结果会用于该测试运单之后的投递尝试，原投递记录和审计会保留。投递列表和打开的投递详情会自动更新状态，待重试时会显示倒计时。右侧投递详情的审计表格按时间倒序分页，每页十条。类型筛选固定在表格上方，分页固定在抽屉底部。查看旧记录时，自动刷新会保留当前阅读位置，并提示符合当前筛选的新增条数，点击「回到最新」可返回第一页。
可在仓库根目录 `.env` 覆盖令牌。令牌只用于管理台，渠道建单和业务回调继续使用各自的签名密钥。

- **运单管理**支持按完整订单号、运单号或物流单号及当前状态筛选，查看轨迹，并按业务状态推进一站、报告异常或恢复运输。
- **回调投递**支持按状态查看最近 500 条投递记录及审计详情。只有已终止的回调可以手动重新投递，提交时填写操作人和原因。

管理台的状态操作复用物流模拟服务的现有状态转换和回调投递机制。只读验收使用 `scripts/fulfillment/verify-logistics-simulator-web.ps1`。

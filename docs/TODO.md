| 功能 | 启动条件和首版边界 |
| --- | --- |
| 账号自助与团队协作 | 有自助用户或多人运营需求时评估注册邀请、邮箱验证、找回密码、安全设置、店铺成员分权。先确认风控、管理者交接、会话撤权与操作审计。 |
| 收藏、到货提醒和通知中心 | 有复访需求时先做收藏、通知历史分页与偏好。到货感知从权威库存事件取事实，覆盖退订、重复到货、下架、投递失败和频率控制。 |
| 商品经营工具 | 有较大商品量时做类目、属性、规格、批量维护和评价治理。先明确商品与 SKU 的稳定标识、库存归属及历史快照。营销图、批量导入和商品比较按操作规模排期。 |
| 搜索体验和推荐 | 搜索查询成本和可见性基线稳定后评估联想、同义词、纠错、类目分面。推荐独立衡量效果，先从规则或非个性化候选开始，再评估授权、数据使用范围和冷启动。 |
| 更丰富的价格与促销 | 已有单店满减。先按业务需要做店铺折扣、满包邮或限时活动中的一种。立项前明确叠加、优先级、归属成本、舍入、核销、返还、部分退款和佣金口径。会员积分、储值或复杂组合另行评审。 |
| 多仓运营与运输 | 首版已有两仓拆履约。后续按仓库规模评估库存盘点流程、调拨、批次、波次、区域运费、分配优先级和第二承运商。先验证原仓退回、短发补偿、运费与幂等规则。 |
| 售后扩展 | 已有同店同 SKU 无差价换货。出现实际需求再评估跨规格换货、差价补收或退回、保修、申诉、平台介入和服务时限。各自明确原支付、补差、库存、结算与税票凭证。 |
| 商家经营与财务 | 扩展商品和售后趋势、分角色导出、结算异议与处理、发票抬头管理。多店铺、分期结算和财务系统对接须先确认授权、结算主体、对账和开票规则。 |
| 多商家交易 | 当前购物车允许多店商品，一次仅结算一家。可先做按店分组和分店下单体验。需要一笔支付覆盖多个商家时，再设计父子单、拆支付、优惠运费分摊、异常补偿、退款、结算和开票归属，单独评审。 |
| 真实渠道接入 | 真实支付、打款、物流、短信邮件和电子发票按实际项目选择。获取目标平台签约与测试环境后，先做协议、回执、对账、权限和失败切换验收，随后评审小流量发布。模拟平台继续服务隔离回归。 |

## 7. 每批交付记录

1. 固定代码版本、候选镜像、数据库版本和环境范围。对修复项记录复现数据、预期、现状和影响，对新功能先固定业务状态、权限、金额及审计口径。
2. 复用 PowerShell 7 的最小回归与专项，涉及状态机、并发或跨库补偿时加入重复、超时、乱序、回执丢失和重启场景。业务账本按请求 ID、订单行或原凭证逐笔核对。
3. 按 [生命周期验收体系](VERIFICATION-SYSTEM.md) 记录测试、历史一致性、候选镜像以及单独的日常抽检和回退证据。默认保留业务卷与历史归档。完成后在本页更新状态，将结果链接到 [实现证据](IMPLEMENTED.md) 或对应专题，并更新受影响的 [功能说明](features/README.md) 和 [API 索引](API.md)。
